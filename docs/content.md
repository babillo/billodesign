# Content

All content is local. There is no CMS (ADR-001).

| What | Where |
|---|---|
| Projects (6) | `content/projects.json`, typed by `Project` in `lib/content.ts` |
| Testimonials (4) | `content/testimonials.json`, typed by `Testimonial` |
| Navigation, social links, services, SEO defaults, orb speech lines | `lib/site.ts` |
| Homepage section copy | inside each component in `components/home/` |
| AI chat system prompt | `lib/chat/system-prompt.ts`: original persona + project/testimonial knowledge generated from `content/*.json` (ADR-012) |

## Where the data came from

`content/*.json` is generated by `scripts/import-webflow.mjs` from:
- `webflow/export/billodesign - Projects.csv` and `billodesign - Testimonials.csv` (official Webflow CMS CSV exports)
- the homepage slider cards and testimonial captions in `webflow/export/index.html`. These were hand-written in Webflow, not CMS-bound, so they differ from the CMS title and summary.

The script:
- keeps only the 6 homepage projects (owner decision) in slider order
- re-points `nextProject` links that targeted removed projects, so the six form a loop:
  personal-brand → orbitai → timms-team → elegantnast → macrostate → flexibank → personal-brand
- fixes typos (Webfow/Weblow → Webflow, Photoshp, Hgh-performance, Fadi Al Ibahim)
- downloads every referenced image into `public/media/projects/<slug>/` and `public/media/testimonials/`, and rewrites URLs
- rewrites Embedly-wrapped Wistia videos to direct Wistia embeds (ADR-009)
- strips Webflow-only attributes from rich text
- records image dimensions for `next/image`

Re-running it overwrites `content/*.json`. **After the first import, edit the JSON directly** rather than the CSVs, unless you re-export from Webflow.

## Project model

```ts
{
  slug, title, summary, publishedOn,
  thumbnail, thumbnailSize,            // header image, "Next Project" card, OG image
  websiteUrl,                          // "Visit Site"
  video: { wistiaId, aspect } | null,  // replaces the header image when set
  meta: { role, timeline, tools, scope, client, industry, market },  // empty values are hidden
  sections: { overview?, challenge?, problemStatement?, ... },       // HTML; missing = hidden
  testimonial: "<testimonial slug>" | null,                          // "Client Feedback" block
  nextProject: "<project slug>",
  card: { title, description, image, imageAlt, imageSize, tools },   // homepage slider card
}
```

Rendered section order and headings are defined in `SECTIONS` in `app/projects/[slug]/page.tsx`.

**Not rendered on purpose:** `strategy` and `userFlow` contain content in the CMS, but the Webflow template never displayed them. They're kept in the data for a possible Phase 6 decision. `meta.scope` is kept but also wasn't displayed.

## How to add a project

1. Add images under `public/media/projects/<slug>/`.
2. Add an entry to `content/projects.json` (copy an existing one). Include `card.imageSize` and `thumbnailSize` (`{ width, height }` in pixels).
3. Point the previous project's `nextProject` at the new slug and the new one at the next.
4. Run `npm run build`. The route, sitemap entry and metadata are generated automatically.

## How to change navigation or social links

Edit `navLinks` / `socialLinks` in `lib/site.ts`. "Contact" in the navbar opens the contact modal and is defined in `components/layout/Navbar.tsx`.

## Rich-text image alt text
Webflow stores `alt="__wf_reserved_inherit"` when no alt was set. The importer (`fixImageAlts`) replaces it with the figure's caption, or "<Project name> screenshot" when there is none. To give an image a better description, edit its caption in the content, or the `alt` in `content/projects.json`.

## Rich-text images are optimized at build time (Phase 7)
`content/projects.json` keeps plain `<img src="/media/...">` tags. `ProjectSection` passes the HTML through `optimizeRichText` (`lib/rich-text.ts`), which:
- points each image at the Next.js image optimizer with a `srcset` (AVIF/WebP, sized to the column), plus `data-full` (1920 px) for the lightbox;
- turns a `.gif` into a looping `<video>` that expects `<name>.webm`, `<name>.mp4` and `<name>-poster.webp` next to where the GIF was.

So you can keep uploading full-size screenshots; visitors get ~25–80 KB versions. Images need `width`/`height` (below), or they're left as they are.

**Adding an animated GIF:** convert it instead of committing it (ffmpeg):
```
ffmpeg -i in.gif -c:v libvpx-vp9 -crf 34 -b:v 0 out.webm
ffmpeg -i in.gif -movflags +faststart -pix_fmt yuv420p -c:v libx264 -crf 28 -preset veryslow -tune animation out.mp4
```
and save its first frame as `out-poster.webp`. GIFs with transparency (like the orb animations) can't be MP4; use animated WebP instead (`sharp(gif, { animated: true }).webp({ quality: 70 })`). Re-running the importer downloads the original GIF again; delete it afterwards.

## Rich-text image dimensions
The importer adds `width`/`height` to every rich-text image (`addImageDimensions`, sizes read with sharp), so the browser reserves the space before the image loads. If you add an image to `content/projects.json` by hand, give it width and height too.

## Project card tags
Each project's `card.tag` is the one-line tag under its title in the homepage grid (e.g. "AI productivity app · Product design & Webflow"). It isn't part of the Webflow CMS: it lives in `CARD_TAGS` in `scripts/import-webflow.mjs` and is written into `content/projects.json`. To change a tag, edit both, or edit `CARD_TAGS` and re-run the importer.

## Site-wide figures (Phase 6)
In `lib/site.ts`:
- `site.availability`: navbar status pill text.
- `performanceStats`: uptime, Lighthouse scores, response time (same figures as the dashboard image).
- `bioStats`: bio strip. Years are computed from `CAREER_START_YEAR = 2022` (web design & development professionally; coding background since 2018) and refresh on each deploy (the homepage is static). Other figures from the owner: 15+ projects, Webflow Certified Partner, Google UX Certified Professional (Google UX Design Professional Certificate). ("Awwwards Nominee" was dropped from the strip on 2026-10-02: "Nominee" only means a site was submitted, so it's a weak credential; the Awwwards ribbon on the right edge stays.)
